# Termo de Abertura do Projeto (Project Charter)

## 1. Identificação

**Projeto:** Agenda Saúde Tacaratu — MVP  
**Versão do documento:** 1.0  
**Data:** 05/11/2026  
**Tipo:** Aplicação Web Full Stack  
**Contexto:** Atividade individual do curso Desenvolvimento Web Full Stack para MVPs, vinculada ao Projeto Agenda Saúde Digital Tacaratu.

## 2. Justificativa

O acesso a informações sobre campanhas e ações públicas de saúde pode ser dificultado quando os comunicados estão dispersos em diferentes canais.

O projeto propõe um protótipo digital simples para organizar e apresentar essas informações em um único ambiente, facilitando a consulta pela população.

Trata-se de uma proposta acadêmica, sem integração com sistemas oficiais ou publicação de dados reais de pacientes.

## 3. Visão Geral do Produto

O Agenda Saúde Tacaratu — MVP será uma aplicação web para visualizar campanhas e eventos de saúde, com informações como título, categoria, descrição, data, horário e local.

O protótipo terá interface responsiva e uma API simples para disponibilizar dados demonstrativos.

## 5. Escopo

### 5.1 Dentro do escopo

- Estruturação do projeto e documentação técnica.
- Organização do backlog no GitHub.
- API para consulta de campanhas demonstrativas.
- Página para listar campanhas e ações de saúde.
- Visualização de informações detalhadas.
- Filtro por categoria.
- Tratamento de ausência de resultados.
- Interface adaptável a computadores e celulares.
- Testes básicos e versionamento com Git.

### 5.2 Fora do escopo

- Prontuário eletrônico.
- Cadastro de pacientes.
- Armazenamento de dados pessoais de saúde.
- Autenticação e controle de usuários.
- Agendamento real de consultas.
- Integração com sistemas do SUS ou da prefeitura.
- Publicação oficial de campanhas.
- Implantação em ambiente de produção.

## 6. Público-alvo

- Moradores de Tacaratu interessados em informações públicas sobre saúde.
- Estudantes e desenvolvedores que desejam compreender um MVP de informação em saúde.

## 7. Stakeholders

| Stakeholder | Interesse |
|---|---|
| Estudante desenvolvedor | Planejar, implementar e documentar o MVP |
| Professor do curso | Avaliar a documentação e o fluxo de engenharia |
| Coordenação da formação | Acompanhar o aprendizado |
| Moradores de Tacaratu | Potenciais usuários da solução |
| Profissionais de saúde | Potenciais interessados na divulgação de ações |

Os stakeholders externos são identificados como potenciais interessados, sem pressupor participação ou aprovação formal.

## 8. Tecnologias Previstas

- HTML5, CSS3 e JavaScript.
- Node.js e Express.
- Git e GitHub.
- Visual Studio Code.
- Markdown para documentação.

## 9. Riscos e Restrições

| Risco | Mitigação |
|---|---|
| Prazo curto | Priorizar funcionalidades essenciais |
| Complexidade excessiva | Excluir autenticação e agendamentos reais |
| Problemas com Git | Utilizar branches temáticas e Pull Requests |
| Uso indevido de informações de saúde | Utilizar somente dados demonstrativos e fictícios |
| Falhas na execução | Registrar testes e corrigir problemas antes da entrega |

## 10. Critérios de Sucesso

O MVP será considerado adequado à atividade quando apresentar documentação rastreável, backlog de pelo menos 15 Issues, uso demonstrável de Git Flow, commits convencionais, Pull Requests, tags de versionamento e funcionalidades básicas implementadas e testadas.

## 11. Entregáveis

- Repositório GitHub público.
- README.md detalhado.
- Quatro documentos obrigatórios na pasta docs.
- Código-fonte na pasta src.
- Backlog organizado.
- Histórico de desenvolvimento e versionamento.
- Evidências do processo.

## 12. Aprovação

Este documento representa o planejamento acadêmico inicial do MVP. Não constitui aprovação formal de implantação pela prefeitura ou por órgãos públicos.
